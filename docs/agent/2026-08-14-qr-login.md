# QR login and credential storage

## Problem

The first gateway required callers to obtain and export `WEIXIN_BOT_TOKEN` themselves. That is workable for protocol development but not a reasonable installation path.

## Decision

The package now installs a `dsh-weixin login` command. It starts the iLink QR flow, follows a regional redirect when Weixin requests one, polls until confirmation, and writes the returned account to `$DSH_HOME/weixin/account.json`. The command never prints the bot token.

On POSIX systems, the parent directory uses mode `0700` and the credential file uses mode `0600`. The plugin rejects a credential file with group or world permissions. `WEIXIN_BOT_TOKEN` still takes precedence for deployments that inject secrets through an environment manager.

The saved regional API base travels with the credential. An explicit `WEIXIN_BOT_API_BASE` override remains available for testing or future endpoint migrations.

## Verification

The QR test uses a fake iLink server sequence covering QR creation, regional redirect, confirmation, private file creation, and credential parsing. The build also runs the compiled CLI help path.
